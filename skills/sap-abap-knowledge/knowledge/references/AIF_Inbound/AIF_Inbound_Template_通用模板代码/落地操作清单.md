## 三、`/AIF/CUST` 登记步骤（7 项）

1. **登记接口**：命名空间 `ZSUP` / 接口名 `ZIF_SUP_PO` / 版本 `1`，方向 **Inbound**。
2. **登记代理类**：入站 = `ZCL_SUP_PO_PROXY`（实现 `ZIF_SUP_PO_STATUS`）。
3. **define structure mapping**：source structure = `Z_SUP_PO_MSG_T1`（**必须与 AIF action FM 里 `ASSIGN data TO <input_wa>` 的类型一致**，否则 `data` 解引用错位）。
4. **assign action**：定义 action `Z_ACT_SUP_PO`，分配给 FM `Z_F_SUP_PO_AIF`。
5. **登记日志对象**：`Z_SUP_PO_LOG_OBJ` / `Z_SUP_PO_LOG_SUBOBJ`（与 SLG1 一致）。
6. **入站校验**：按你的安全要求配签名 / 认证 / 接口授权（本模板**未配**，是已知缺口 1.4）。
7. **激活 + 传输**：`/AIF/CUST` 激活接口；若目标系统有开发工作台，走传输请求。

**关键**：第 3 步的 source structure 是**最容易踩的坑**——AIF action FM 里 `ASSIGN data TO <input_wa>` 的 `<input_wa>` 类型必须等于这里登记的 source structure，否则运行时 `data` 解引用到错误结构。

## 五、`GET_DATA` 内部要改的地方（4 处）

模板里的 `GET_DATA` 是**骨架**，落到你的业务要改：

1. **取数 SELECT**：`FROM z_your_bkpf_view / z_your_bseg` 换成你要读的 CDS view / 表；`WHERE accounttype = 'D'` 换成你的业务口径。
2. **变更字段**：`ls_accchg-fdname = 'REF1'` 等三条 `fdname/oldval/newval` 换成你要改的凭证字段（或改成你要改的 FM 入参）。
3. **改记录的 FM**：`FI_DOCUMENT_CHANGE` 换成你要改的 FM（`BAPI_ACC_DOCUMENT_MODIFY` / CDS update / 自定义 FM 等）。
4. **邮件 body 拼接**：`TEXT-001..012` 换成你的文本元素；`lv_subject = TEXT-006` 换成你的邮件主题。

**不动的地方**（模板里已写对的，保留）：
- 循环内 `CLEAR lt_accchg`（P0-1）
- `save_all_logs` 前判 `IS BOUND`（P0-2）
- `update_message` 前判 `lr_enabler IS BOUND`（P1-10）
- 邮件失败 `TYPE 'W'`（P1-7）
- `emails` 判空（P1-11）
- 未找到分支三处类型统一 `E`（P2-2）
- `READ TABLE ... BINARY SEARCH`（P2-1）

## 七、常见踩坑（5 项）

1. **source structure 与 `ASSIGN data` 类型不一致** → `data` 解引用错位，AIF 引擎报"消息结构不匹配"。
2. **`/AIF/CUST` 登记的日志对象与 SLG1 不一致** → 日志写到别的对象下，应用日志里看不到。
3. **消息类未激活** → 运行期 `gen_log_obj->add_message` 短转储。
4. **EFR 应用 ID 拼写错**（原 P0-3 `UDPATE` 教训）→ 配置读不到 → 公司代码/邮箱全空 → 整批 005。
5. **代理类里写了业务逻辑** → AIF 重新生成代理类时业务被覆盖。**代理类方法体只保留一句 `EXECUTE_ASYNC_WS`**。

## 八、传输到目标系统（3 步）

1. **开发系统**：完成第 1–9 步，`/AIF/CUST` 激活接口，走开发工作台创建传输请求（如 `ZSUPPO01`）。
2. **质量系统**：导入传输请求，重新走第五节编译顺序，跑第六节测试清单。
3. **生产系统**：导入传输请求，激活，跑一次**测试消息**（`testrun = 'X'`，不实际改记录），确认链路通后再放开正式消息。
